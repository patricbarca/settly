# Settly — Claude Context

## What this app is
Settlia (plain wordmark — the old **Settl·iA** "iA" accent was dropped; it's just **Settlia** everywhere now) is a PWA for splitting group expenses. Stack: React 18 + Vite 6 + TypeScript + Tailwind CSS v4. Deployed via GitHub Actions to GitHub Pages on the custom domain **`app.settlia.app`** (Vite `base: "/"`). The marketing landing is **`settlia.app`**.

> **Rebrand history:** was "Settly", briefly "Cow.ai", now **SettliA** with Settly's original colors/logo (teal `#0FA3A3` / indigo `#5B5BF0`, two-circle+check mark). The pre-rebrand state is preserved on the `settly-original` branch of both repos.

## Key files

- `src/lib/plan.ts` — freemium plan + AI-quota scaffolding (free/pro + monthly scan count in localStorage). **Free = max 3 active groups (`FREE_GROUP_LIMIT`)**; creating a 4th opens the Paywall (gated in `Home.startCreate`). Pro = unlimited. Plan from Supabase `entitlements` via access codes.
- `src/components/Paywall.tsx` / `InstallButton.tsx` — upgrade modal and PWA install button (`src/lib/pwa.ts` captures `beforeinstallprompt` + iOS detection)
- `src/components/GroupView.tsx` — main group screen (tabs: Expenses, Balances, Stats, Achievements)
- `src/components/Hero.tsx` — hero card inside GroupView (group name + total/owe/owed pills + Settle Score ring)
- `src/components/ExpenseForm.tsx` — add/edit expense form (voice input, receipt scan, recurring toggle)
- `src/components/RecurringList.tsx` — recurring expenses list (hidden when empty)
- `src/components/AddForm.tsx` — wrapper for the add expense flow
- `src/lib/auth.ts` — Supabase Auth (Google + email/OTP); phase machine incl. a **guest** mode for testing; reads/persists `profiles.avatar` (Google photo by default); `setProfileAvatar`/`setProfileName`. Phone step is optional in beta.
- `src/lib/ai.ts` — client for the AI Edge Functions: `parseExpenseAI` (text→expense), `scanReceipt` (vision), `transcribeAudio` (server STT via the `transcribe` function → Groq/Whisper)
- `src/lib/speech.ts` — `useSpeech(onText, lang)` dictation hook. Web Speech on Android/desktop; **on iOS records→server STT** (`transcribeAudio`, since iOS exposes a broken `webkitSpeechRecognition`). Needs connection (offline → add expense manually). Follows the ES/EN toggle. Exposes `listening`/`busy`/`error`.
- `src/lib/parse.ts` — local (regex) natural-language → expense parser + category + recurrence interval (fallback when the LLM isn't deployed)
- `src/lib/contacts.ts` — `getNetwork()`: registered users you share groups with (for the create-group selector). Returns `{userId,name,avatar,email}`, **ordered by most-recently-active shared group** (excludes archived/trashed). Requires the `View co-members` RLS policy (see migrate_v4) — without it the network is always empty (RLS only let you read your own `group_members` rows). Members are **registered-only**: CreateGroupModal + UsersModal search by email/name; the "add without account" (manual) flow was removed (non-users join by invite link). UsersModal has a search bar over the suggestions.
- `src/lib/image.ts` — `fileToAvatarDataUrl()` crop/resize an uploaded photo to a small JPEG data URL
- `src/components/Avatar.tsx` — renders a member's photo (`<img>` for URL/data URL) or emoji/initials fallback
- `supabase/functions/parse-expense|scan-receipt|transcribe/` — Deno Edge Functions, all on **Groq** (OpenAI-compatible API, key `STT_API_KEY`). `parse-expense` (text→expense, **`openai/gpt-oss-20b`** desde 2026-10-17; Groq retiró los Llama), `scan-receipt` (vision, **`qwen/qwen3.6-27b` en Groq** — reemplazo del deprecado Llama 4 Scout — **con FAILOVER + hedging a un backup** (`AI_VISION_BACKUP_API_KEY`, def. OpenRouter `openai/gpt-4o-mini`): si el primario no contesta en 7 s se dispara el backup en paralelo y gana el primero. No `response_format` here: Groq vision returns `json_validate_failed` under strict JSON mode, so we rely on the prompt + `extractJson` (que además limpia bloques `<think>`). En Groq se manda `reasoning_effort:"none"`), `transcribe` (STT, `whisper-large-v3-turbo`). All use `response_format: json_object` + **server-side sanitize**. **Las tres desplegadas** (`scan-receipt` **v53**, 2026-09-25).
- `supabase/setup_all.sql` — idempotent full schema (tables + RLS + `redeem_access_code` SECURITY DEFINER fn + `profiles.avatar`). Includes `is_member_of()` SECURITY DEFINER + `View co-members` policy so the network/suggestions work.
- `supabase/migrate_v4_network_rls.sql` — **run once in SQL Editor** on existing DBs: adds `is_member_of()` + `View co-members` SELECT policy on `group_members` so `getNetwork` can read other members of your groups (fixes empty suggested list). Definer fn avoids RLS recursion.

## Design system
- **Glass morphism**: `.glass` and `.glass-strong` utility classes with `backdrop-filter` + reflejo (`--glass-sheen`, como `background-image`) y borde de luz arriba/abajo. **`.glass-chrome`** = cristal de las barras fijas (barra inferior flotante, cabecera compacta del grupo).
- **iOS fix**: `@supports (-webkit-touch-callout: none)` disables backdrop-filter on iOS Safari **en `.glass`/`.glass-strong`** (corner artifact bug), falls back to opaque `--glass-solid` / `--glass-strong-solid` variables (solo cambia `background-color`; el reflejo se mantiene). **`.glass-chrome` SÍ lleva blur en iOS**, recortado con el truco `-webkit-mask-image` del hero (⚠️ sin probar aún en iPhone).
- **Patrones iOS (2026-10-13):** pestañas del grupo = control segmentado `.seg` (`aria-selected`); modales (`Overlay`) = **hoja inferior** en móvil (`.sheet-overlay`, asa + arrastrar para cerrar; `center` para el visor de recibos); `hover-lift` solo levanta con ratón (`@media (hover: hover)`) y al pulsar encoge (`scale(.97)`); vibraciones con `haptic()` (`src/lib/haptics.ts`).
- **Colors**: `--teal` (#0FA3A3), `--indigo` (#5B5BF0), `--coral` (#FF5A4D), `--amber` (#E8920C), `--ink`, `--muted`
- **Fonts (2026-10-13): fuente del SISTEMA para toda la UI** (`--font-ui` / `--font-ui-display` en `src/index.css`: SF Pro en iPhone/Mac, Roboto en Android) en `body`, `.font-display` y `.font-mono` (con `tabular-nums`). **Baloo 2 queda SOLO para el wordmark "Settlia"** → clase **`.font-brand`** (`--font-brand`), usada en el hero de `Home`, `Login`, el splash de `App.tsx` y la cabecera de `ReportModal` (y `InstallDemoAnim`, inline). Baloo 2 sigue auto-hospedada en `src/fonts.css`. Historia: #257 puso la del sistema en todo; el usuario pidió volver a Baloo 2 y luego afinó a "Baloo solo para el nombre". ⚠️ **NO hay Bricolage Grotesque, ni Instrument Sans, ni Space Mono en la app** — esta ficha decía eso y era falso, lo que llevó a construir el mockup de la landing con tres fuentes equivocadas. `.font-mono` **no es monoespaciada**: los importes se ven en Baloo 2 como el resto.
- **Rounded corners**: all cards use `rounded-3xl`
- **Dark mode**: `[data-theme="dark"]` on `<html>`

### Reparto DESIGUAL por porcentajes desde el prompt ("supermarket 150 60% me") (2026-09-30)
- **Qué hace:** escribir un porcentaje en la nota ahora define **cuánto le toca a cada uno**, no cuánto puso. `supermarket 150 60% me` → gasto de 150 con **mi parte al 60%** y el 40% restante a partes iguales entre el resto de participantes. Funciona con varios (`rent 900 50% me 30% Emma 20% Liam`) y en ES/EN.
- **Tres capas, las tres tocadas:**
  1. **`src/lib/parse.ts`** (parser local, offline/gratis): `ParsedExpense.percents` + `extractPercents()`. El porcentaje se ata a la persona **pegada por delante** primero y solo después hasta 3 tokens por detrás — ese orden es el que resuelve `yo 60% Emma 40%` (buscando hacia delante primero, el 60% se lo llevaba Emma), y una persona ya asignada no se reclama dos veces. Lo que sobra hasta 100 se reparte **a partes iguales entre los participantes sin porcentaje explícito**; si no queda nadie, se normaliza a 100. El monto ignora los números seguidos de `%` (antes `supermarket 45, yo 60%` agarraba el 60 como importe).
  2. **`supabase/functions/parse-expense/index.ts`** (LLM, **desplegada v43**): nueva clave `percents` en el esquema + regla de dos casos y 3 ejemplos few-shot. `sanitizePercents()` server-side: solo acepta un reparto **completo** (cubre a TODOS los participantes) que **sume 100 ±0.5**; cualquier otra cosa → `null` y el gasto va a partes iguales. Se **revalida después del pipeline** porque `applyDefaultSplit` puede ampliar `participantIds` tras la primera validación.
  3. **`src/components/AddExpense.tsx`**: `sanitizePercents()` espejo en cliente y el borrador entra con `splitMode:"percent"` + `splitValues`, así el formulario muestra el reparto y se puede corregir a mano. La línea de resumen de la IA sustituye "entre N" por `60% Alex · 40% Emma`.
- **⚠️ CAMBIO DE COMPORTAMIENTO:** antes el prompt del LLM decía que un porcentaje indicaba **quién pagó** (`"Súper 45, yo 60% y Ana 40%"` → dos pagos de 27 y 18). Ahora eso es un **reparto** 60/40 pagado por uno. Los porcentajes solo significan pagos cuando van **inmediatamente detrás de un verbo de pago** (`yo pagué el 60%`).
- **Fail-safe deliberado en el parser local:** si la nota contiene CUALQUIER verbo de pago (`pagué/pagó/paid/puse/puso/...`), el parser de regex **no intenta** el reparto desigual y deja el gasto a partes iguales. Con un verbo de pago mezclado (`taxi 30 pago Emma, 60% yo 40% ella`) no hay forma fiable de distinguir "cuánto puso" de "cuánto le toca" con regex, y repartir mal el dinero en silencio es peor que un reparto igualitario que el usuario ve y corrige. Ese caso lo resuelve el LLM, que sí modela pagadores.
- **Tolerancia de "todos iguales" a 0.5 puntos** (en cliente y servidor): `33.34/33.33/33.33` ES un reparto a partes iguales redondeado; marcarlo como desigual ensucia el gasto con splits que no aportan nada.

### Fix clobber de pagos: escrituras de blob completo ya no pueden borrar un settlement
- **Síntoma real (grupo Canberrita Home):** Javi marcó un pago, llegó la notificación push (llamada aparte a `send-push`), pero el pago **nunca quedó en la DB** — ni settlement, ni actividad, ni para confirmar. Nada, ni en web ni iOS.
- **Causa raíz:** `persist()` y `syncOutbox()` (`store.ts`) escribían el **JSON COMPLETO** del grupo (`update ... set data = <copia local>`). Aunque los pagos se añaden con la RPC atómica `add_settlement`, **cualquier** escritura de blob posterior desde un cliente con datos viejos (otro dispositivo, o un back-fill SQL) **sobrescribía todo el `data`**, borrando el settlement recién añadido → pago perdido en silencio. Es el "clobber" que ya advertía CLAUDE.md.
- **Fix (`migrate_v12` + store.ts):** `persist`/`syncOutbox` ahora van por la RPC **`update_group_data`** (SECURITY DEFINER, chequea membresía) que escribe el blob PERO **une por id** los arrays append-only **settlements/notifications/activity** con lo que ya hay en el servidor (helper `jsonb_union_by_id`): el **servidor gana** en conflicto de id (un blob viejo no revierte un confirm) y se **añaden** los items nuevos del cliente (pagos offline). Verificado: `union(server[a:confirmed], client[a:pending, b])` = `[a:confirmed, b]`. **Un blob viejo ya no puede borrar ni revertir un pago.**
- **Independiente del cambio de settle-up optimista:** ese solo tocó cómo se MUESTRAN los pagos; la ruta de escritura (y este bug) es pre-existente. Podía pasar igual antes.
- **Pendiente (Fase 2):** mismo trato para **members/expenses** en el blob; y **avisar al usuario** cuando una escritura falla (hoy reintenta silenciosa vía outbox).

## ⚠️ Regla permanente: estructura de costes de la IA (hedging factura DOBLE)
- **FÓRMULA REAL del coste por escaneo** — no es el precio del primario:
  `coste = P_primario + (tasa_hedge × P_backup)`
  `tasa_hedge` = % de escaneos en los que el primario tarda **>`HEDGE_MS` (7 s)** → `scan-receipt` lanza el backup **EN PARALELO** y **se facturan LOS DOS**, descartando una respuesta. Al presupuestar, **contar siempre el peor caso (ambos proveedores)**, nunca solo el primario.
- **Dos palancas, y tiran en sentidos distintos:**
  - **`HEDGE_MS` ↑** → menos doble facturación **y** menos "ruleta de modelo" (ver abajo), a cambio de más latencia en el peor caso. Es la palanca que mejora coste **y** calidad a la vez.
  - **Modelo mejor** → más precisión, más precio por llamada.
- **✅ RESUELTO (v54): el PRIMARIO manda, salvo fallo real.** El hedging premiaba al **RÁPIDO, no al mejor**: el viejo `firstOk([pPrimary, pBackup])` servía al primero que contestara OK, así que con un primario fuerte y un backup flojo **pagabas por el bueno y a veces recibías el malo**. Ahora `preferPrimary(pPrimary, pBackup)`: la respuesta OK del primario **gana siempre**, aunque el backup llegara antes; el backup solo se sirve si el primario **falla**, o si sigue pendiente **`PRIMARY_GRACE_MS` (4 s)** después de que el backup respondiera bien (así no se espera el timeout completo de 25 s). Si ambos fallan se reporta el error del **primario**. El hedging sigue **disparándose** a los `HEDGE_MS` (protege la latencia) → **la doble facturación no cambia**, solo cambia **qué respuesta se sirve**.
- **Regla de decisión por volumen** (medido 2026-09: **53 escaneos en 4 meses ≈ 20/mes**):
  - **< ~500 escaneos/mes → elegir por PRECISIÓN, el precio es ruido.** Toda la horquilla entre el VLM más barato y el más caro son **~$0.38/mes** a 20 escaneos. Un escaneo mal leído cuesta más en confianza que la diferencia entera.
  - **> ~1.000 escaneos/mes → empezar a mirar el precio** (ahí la horquilla se va a ~$19/mes).
- **La cuenta que escala = coste por usuario Pro contra los $6.99.** Con la cuota Pro (30 escaneos/mes) **agotada entera**: modelo barato ≈ **0.4%** del ingreso, modelo caro ≈ **8.6%**. Margen sano incluso en el peor caso — por eso la precisión gana.
- **Groq NO va para visión** (ya deprecó Scout y Maverick; su catálogo multimodal es delgado). Groq se queda para **texto y voz** (`parse-expense`, `transcribe`, `STT_API_KEY`). Visión va por `AI_VISION_*`.
- **Cómo probar un modelo nuevo:** cambiar `AI_VISION_MODEL` es **un secreto del dashboard, sin despliegue**. Caso de prueba con respuesta conocida: el **ticket de Pampero** → **$304.00, 10 líneas, tres a $36.00** (trampas: `36`/`38`, `(2) x 2`, y dos subtotales).

## Multi-session / concurrency notes
- CLAUDE.md is a normal repo file — it is **not** auto-updated; it only changes when a session edits + commits it. Keep it current manually.
- **Multiple Claude sessions can run on the same repo at once.** Git does not auto-merge silently: edits land via commits/PRs, and concurrent edits to the same lines cause merge conflicts (not silent loss). Risk of clobbering exists mainly when two sessions push to the **same branch** with force-push.
- Safe pattern (what we use): one branch per session, `--force-with-lease` (fails if remote moved), squash-merge to `master`, then `git reset --hard origin/master` before new work to pick up other sessions' merges.
